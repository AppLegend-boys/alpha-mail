# 음성 모드 흐름 보완 설계 (2026-11-07)

## 왜

운전하거나 걸을 때 **화면을 보지 않고** 메일을 듣고, 넘기고, 계정을 바꾸고, 답장까지 말로 끝내고 싶다. 지금 음성 모드 홈(`lib/screens/voice_home.dart`)은 “읽어 줘 / 나중에 / 다음 / 그만”만 알아듣고, 답장은 화면의 메일 작성으로 넘어가 손이 필요하다. 게다가 읽는 중 “그만”이 실제로 안 먹힌다.

## 목표

1. 읽는 중 끼어들기(“그만”, “다음”, “지메일로 바꿔 줘”)가 실기기에서 확실히 동작한다.
2. 단어 목록(하드코딩) 대신 기기 안 Gemma가 말뜻을 판단한다. 아주 기본적인 말만 규칙으로 남긴다.
3. 말로 답장: 하고 싶은 말을 대충 말하면 Gemma가 메일 문장으로 쓰고, 소리로 읽어 확인한 뒤 “보내”로 보낸다.

## 하지 않는 것 (non-goals)

- 새 메일 쓰기(“철수한테 메일 보내 줘”). 받는 사람 주소를 말로 정확히 듣는 건 별도 문제.
- 터치 모드 홈(`home.dart`), `BriefingScreen`, 메일 작성 화면(`compose.dart`)의 명령은 그대로 둔다.
- 이전 메일, 다시 읽기, 속도 조절 같은 새 명령은 이번에 넣지 않는다 (Gemma 행동 목록에 나중에 추가 가능).

## 실패로 보는 것 (anti-goals)

- 사용자가 “보내”라고 확실히 말하지 않았는데 메일이 나감.
- “그만”이 무시되거나, 말이 끝난 뒤 멈출 때까지 체감 1.5초를 넘음. (내 판단: 0단계에서 실측하고, 넘으면 VAD 침묵 0.6초 조정까지 0단계 범위)
- 메일 내용이나 음성이 기기 밖으로 나감 (AGENTS.md 규칙).

## 제약

- Gemma 4 E2B(2.6GB, `lib/mail/summary.dart`의 `Summarizer`)는 선택 다운로드. 세션이 하나라 한 번에 한 일만 한다(`_lock`).
- 마이크는 읽는 중에도 에코 제거로 듣는다(`_hearCommands`). 폰 목소리 일부가 글자로 새어 들어올 수 있다.
- 오프라인, 기기 안 처리만. 폰 앱만.

## 접근 방법

| 방법 | 장점 | 단점 |
|---|---|---|
| 1. 단어 규칙 넓히기 | 즉시 반응, 모델 불필요 | 목록 밖 표현은 못 알아들음, 계속 하드코딩 |
| **2. Gemma가 해석 + 기본 규칙 몇 개 (선택)** | 자유롭게 말해도 알아들음, 규칙 관리가 줄어듦 | 명령마다 1~3초, 모델 필수, 요약과 세션 공유 |
| 3. 규칙 먼저, 못 알아들으면 Gemma | 유연 | 두 갈래를 다 만들고 반응 속도가 들쭉날쭉 |

사용자가 고른 것: 모양은 3번(규칙 먼저, 나머지 Gemma)이지만 무게는 2번. Gemma가 주 해석기이고, 규칙은 늦으면 안 되는 말(그만·다음)과 AI에 맡기면 안 되는 말(보내·취소·다시) 다섯 개로 고정해 늘리지 않는다. 하드코딩된 단어 목록은 지운다.

## 설계

### 0. 먼저: 읽는 중 “그만”이 안 먹히는 버그

원인부터 실기기(갤럭시 SM S948N)에서 찾는다. `superpowers:systematic-debugging`으로. 의심:
- 폰 목소리가 새어 VAD가 말 끝을 못 잡아, 문장이 낭독이 끝난 뒤에야 넘어옴.
- 낭독 중 녹음이 실제론 멈춰 있음(오디오 포커스·세션).
- 넘어온 글자에 낭독 문장이 섞여 규칙에 안 맞음.

고친 뒤 `TROUBLESHOOTING.md`에 남긴다. 이 단계가 안 풀려도 “묻는 중” Gemma 해석과 말로 답장은 읽는 중 끼어들기와 상관없으니 먼저 진행하고, “읽는 중” 부분만 설계를 다시 본다. (내 판단)

### 1. 규칙으로 남기는 말 (기본 규칙)

`lib/voice/`에 한 곳으로 모은다. 그 외 단어 목록(`isYesCommand`, `isLaterCommand`, `isSkipCommand`의 음성 홈 사용)은 음성 홈에서 지운다. 터치 홈·`BriefingScreen`·`compose.dart`가 아직 쓰는 함수는 남긴다.

| 말 | 언제 | 동작 |
|---|---|---|
| 그만, 멈춰 | 언제나 | 즉시 멈춤 (`_quit`) |
| 다음 | 읽는 중 | 즉시 다음 메일 |
| 보내 | 답장 확인 중에만 | 보냄 |
| 취소 | 답장 확인 중에만 | 안 보내고 읽던 메일로 |
| 다시 | 답장 확인 중에만 | 답장 내용을 처음부터 다시 말하기 |

“다음”·“보내”는 지금 `_skip`처럼 **그 말만** 했을 때만 맞춘다 (본문 “다음 주…”, 주변 대화 오인 방지).

### 2. Gemma가 판단하는 말

규칙에 안 맞는 문장은 Gemma에 넘겨 **정해진 행동 하나**를 JSON으로 받는다. 앱은 목록 밖 값이나 깨진 JSON을 “못 알아들음”으로 처리한다 (`_missed`).

```json
{"action": "read", "mails": [1, 0]}
```

프롬프트에 메일 목록(최대 30개, 안 읽은 것 먼저, 이번 대화에서 읽은 것은 “이미 읽음”)을 번호와 함께 넣고, Gemma가 읽을 번호를 순서대로 고른다. 코드는 없는 번호·겹치는 번호만 걸러 낸다. 처음엔 `service`·`only`·`today`·`from_start` 표시로 받아 코드가 걸렀는데, Gemma가 말하지 않은 조건까지 채워 “네이버만”이 “오늘 온 것만”이 되는 일이 있었고, 보낸 사람으로 고르기 같은 말마다 규칙이 늘어나 번호 고르기로 바꿨다 (2026-11-11). 음성인식이 비슷한 소리로 잘못 적을 수 있다(“이거줘” ≈ “읽어 줘”)는 안내도 프롬프트에 넣는다.

행동 목록:
- `read`: 읽기 시작 또는 읽는 순서 바꾸기. `mails`가 없으면 안 읽은 메일 순서대로, 빈 목록이면 “말씀하신 메일이 없어요.” (“네이버 메일만”, “지메일부터”, “지메일로 바꿔 줘”, “처음부터 다시”, “오늘 온 거”, “박서준 메일”)
- `later`: 나중에 / 끝내기
- `reply`: 지금 읽는 메일에 답장 시작 (3번 흐름). 내용이 같이 있으면 `{"action":"reply","content":"…"}`로 받아 “뭐라고 보낼까요?”를 건너뛰고 바로 초안을 쓴다 (“괜찮다고 보내자”, “내일 간다고 답장해 줘”, “이렇게 보내 줘: …”)
- `none`: 명령이 아님 (주변 말, 새어 든 낭독 글자) → 아무것도 안 하고 계속

프롬프트에는 연결된 계정 서비스 이름과 지금 상태(묻는 중 / 읽는 중)만 넣는다. 메일 본문은 넣지 않는다.

조건에 맞는 메일이 없으면 “지메일에는 안 읽은 메일이 없어요”처럼 말하고 다시 묻는다.

**Gemma가 없을 때** (모델 안 받음): 기본 규칙만 동작한다. 처음 큰 마이크를 누르면 지금처럼 “읽어 드릴까요?”를 묻고, 이때 그만·나중 외의 말은 모두 “읽어 줘”로 본다. 한 번 “요약 모델을 받으면 더 많은 말을 알아들어요”라고 안내한다.

**기다리는 동안**: 알약에 지금처럼 ‘확인하고 있어요’. 읽는 중이면 낭독을 잠깐 멈추지 않고 이어 가다가, 결과가 행동이면 그때 바꾼다 (`none`이면 아무 일 없음).

**세션 순서**: 명령 해석이 요약보다 먼저다. 요약을 끊지 않고 같은 `_lock`을 기다린다(`Summarizer.complete`). 낭독은 요약이 다 써진 뒤에 시작하므로, 읽는 중에 말하면 모델은 비어 있다.

### 3. 말로 답장

```
나: "답장해 줘"           (Gemma → reply)
앱: "뭐라고 보낼까요?"
나: "괜찮다고, 내일 3시에 보자고 해 줘"
앱: (Gemma가 메일 문장으로 씀)
    "이렇게 보낼게요. '…' 보낼까요?"
나: "보내"  → 보내고 "보냈어요." 후 다음 메일 이어 읽기
    "고쳐 줘, 4시로" → Gemma가 고친 문장을 다시 읽음
    "다시"  → "뭐라고 보낼까요?"로 돌아감
    "취소"  → 안 보내고 읽던 메일 다음으로
```

- 초안을 읽는 동안엔 마이크를 끄고, 다 읽은 뒤에만 “보내/취소/다시”를 듣는다. 초안 낭독이 새어 “보내”로 맞는 걸 막기 위해. (내 판단)
- 보내기는 규칙 “보내”로만. “응”, “네”, Gemma 판단으로는 절대 안 보낸다.
- 확인 단계에서 “보내/취소/다시”가 아닌 말은 Gemma에 “고쳐 달라는 말”로 넘긴다. “4시로 보내자”처럼 ‘보내’가 섞여도 바로 보내지 않고, 고친 초안을 다시 읽고 “보낼까요?”를 묻는다 (규칙 “보내”는 그 말만 했을 때).
- 받아쓰기는 2초 동안 조용하면 끝으로 보고, 그 전 조각은 이어 붙인다 (사용자 결정).
- 보내는 계정은 그 메일을 받은 계정, `MailAccount.send(replyTo: mail)` 재사용 (`compose.dart` `_send` 참고).
- 문체: 존댓말, 받은 메일 말투에 맞춤. 프롬프트에 받은 메일의 보낸 사람·제목·본문 앞부분을 넣는다 (기기 안).
- 화면에는 대화 말풍선으로 답장 초안을 보여 준다.
- **Gemma가 없을 때**: 말로 답장은 안 된다. “요약 모델을 받으면 말로 답장할 수 있어요”라고 안내하고, 화면의 ‘답장할래’ 버튼(작성 화면)은 그대로 둔다 (사용자 결정, 규칙 다섯 개 유지).
- 보내기 실패는 오류 문구를 읽어 주고 “다시 보낼까요?” (보내 / 취소).

### 화면 상태

`VoiceStep`에 답장 단계 추가(받아쓰는 중, 쓰는 중, 확인 중, 보내는 중). 알약 문구는 `pillText`에 이어서.

### 테스트

- 기본 규칙 함수: 맞는 말 / 본문 속 “다음 주”, “보내 주신” 같은 오인 사례.
- Gemma 결과 파서: 정상 JSON, 깨진 JSON, 목록 밖 값, 없는 서비스.
- 번호 고르기(`pickMails`)·JSON 읽기(`parseIntent`)·프롬프트(`intentPrompt`)를 순수 함수로 빼서 테스트.

## 만드는 순서

1. 읽는 중 “그만” 버그 원인 찾고 고치기
2. 기본 규칙 정리 + Gemma 명령 해석 + 계정·순서·날짜 고르기
3. 말로 답장

## 빌더에게 맡기는 것

- 프롬프트 문구, JSON 추출 방식(예시 몇 개 넣기 등)
- 새 파일을 둘지(`lib/voice/commands.dart` 등) `summary.dart`에 붙일지
- 말풍선 모양 세부
